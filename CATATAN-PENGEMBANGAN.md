# Integrity Decision Lab — versi lengkap 1.0

Versi ini melengkapi pembukaan dan Misi Deteksi yang telah disetujui dengan Pertimbangkan, Teladankan, Strategikan, Strategy Canvas, debrief, job aid, refleksi, dan penutup. Tampilan memakai ilustrasi kantor 2D, kartu map, kertas arsip, warna hijau gelap dan kuningan, serta font lokal. Animasi pembukaan tetap menggunakan standar “Lebih terlihat” dengan amplitudo 1,65.

## Sumber dan keputusan produksi

Sumber utama: **Storyboard Integritas Lanjutan (2).pptx** (33 slide) dan **Masukan Diskusi awal project game story.docx**, serta persetujuan dalam percakapan. Katalog desain dan ilustrasi yang sudah disetujui digunakan kembali.

| Bagian | Sumber / penerapan |
| --- | --- |
| Pembukaan | Kedatangan, resepsionis, amplop, empat kartu misi, panduan, empat lensa, dan peta. Narator berupa teks mengetik; tidak ada audio. |
| Misi 1 | Slide 10–14: rekomendasi fiskal, tenggat dua hari, hipotesis A/B, berkas data/metode/tim/konteks, pilihan analisis A–D. |
| Misi 2 | Slide 17–19: asumsi penerimaan optimistis yang masih mungkin secara teknis tetapi dukungan buktinya lebih lemah; empat respons A–D. |
| Misi 3 | Slide 22–24: konsistensi standar saat perbedaan pendapat memiliki konsekuensi; dua tindakan A/B dan refleksi wajib. |
| Misi 4 | Slide 27–29: enam intervensi A–F; minimum dua, maksimum empat; analisis kombinasi lalu Strategy Canvas. Judul diseragamkan menjadi Strategikan. |
| Akhir | Slide 31–33: kualitas analisis, ringkasan keputusan, job aid, refleksi, dan dialog lobi. |

Arahan akhir pengguna dipakai untuk memperjelas butir yang sebelumnya belum tersedia. Fakta/gejala/risiko/dugaan akar pada Misi 1 adalah panduan berpikir, bukan tugas klasifikasi eksklusif. Sapaan memakai “Anda”; tombol hasil memakai “Lihat Konsekuensi”. Adegan menuju Ruang Deteksi memakai ruang analisis. Placeholder tanggal/lokasi tidak dipakai.

Kasus tambahan “Menjelang Akhir Tahun Anggaran” pada gambar slide 30 dan Final Challenge paket keputusan dari rancangan lama tidak dimasukkan, mengikuti keputusan sebelumnya. Game berakhir dengan empat misi dalam satu kasus rekomendasi fiskal.

## Adaptasi yang dibuat untuk implementasi

Pilihan pokok dan fakta kasus mengikuti sumber. Dialog cabang, uraian konsekuensi yang tidak dicontohkan pada slide, hubungan antarmisi, isi pilihan Canvas, dan aturan dashboard adalah adaptasi produksi. Tidak ditambahkan angka fiskal, pasal, SOP, atau otoritas institusional yang tidak disediakan.

Misi 2 memperlihatkan empat hasil berbeda: keterbatasan justifikasi rentang teknis (A), pemeliharaan basis bukti dan pembandingan skenario (B), risiko pengalihan tanggung jawab (C), dan biaya penundaan tanpa prioritas (D). Misi 3 memperlihatkan konsistensi standar (A) atau risiko normalisasi pengecualian (B). Pengantar masing-masing misi merujuk keputusan final misi sebelumnya.

Kalimat pembuka Misi 3 diadaptasi menjadi ajakan menyampaikan keraguan pada pembahasan saat itu. Ini menjaga kesinambungan pada seluruh jalur, termasuk pemain yang belum mengutamakan ruang keberatan pada Misi 2.

Pemain dapat merevisi setelah melihat konsekuensi, sebelum menekan Tetapkan. Pilihan pertama dan jejak revisi tetap dicatat; dashboard membaca pilihan yang ditetapkan. Semua jalur dapat mencapai akhir. Refleksi hanya diperiksa keterisiannya dan tidak dianalisis atau dinilai otomatis.

## Intervensi dan Canvas

Ada 50 kombinasi yang diizinkan: C(6,2) + C(6,3) + C(6,4). UI menonaktifkan opsi kelima dan memerlukan minimum dua sebelum lanjut.

| Intervensi | Fungsi dalam ulasan kombinasi |
| --- | --- |
| A | Standar sumber, validasi, dan dokumentasi asumsi. |
| B | Reviu kualitas pada titik keputusan kritis. |
| C | Pencatatan perbedaan pendapat dan jalur eskalasi. |
| D | Dukungan kemampuan individu; tidak dianggap pengganti perbaikan proses. |
| E | Evaluasi target, insentif, dan praktik kerja. |
| F | Bahasa nilai bersama; tidak dianggap pengganti mekanisme proses. |

Canvas wajib diisi: Pola, Akar, Intervensi, Indikator. Kolom Intervensi mengambil pilihan pemain dan memilih satu fokus pelaksanaan; kombinasi keseluruhan tetap disimpan.

| Hubungan yang ditinjau | Aturan |
| --- | --- |
| Pola–Akar | Topik sama: data, ruang keberatan, atau tekanan kerja. Penjelasan tunggal “ketelitian individu” belum cukup menghubungkan pola dalam kasus. |
| Akar–Intervensi | A menjawab data; B dapat menanggapi data/keberatan/tekanan melalui titik reviu; C menjawab ruang keberatan; D menjawab pembinaan individu; E menjawab tekanan kerja. F sendiri belum menjadi mekanisme untuk akar proses. |
| Intervensi–Indikator | A → bukti sumber/validasi/asumsi; B → reviu dan tindak lanjut; C → keberatan yang ditelaah dan ditindaklanjuti; E → perubahan praktik beserta kualitas. Kehadiran pembinaan/sosialisasi belum membuktikan perubahan proses. |

Pemain boleh menetapkan Canvas yang memiliki celah setelah membaca tinjauannya. Celah tersebut tetap muncul dalam dashboard. Aturan ini bersifat rubrik pembelajaran untuk kasus, bukan standar penilaian kinerja pegawai.

## Dashboard kualitatif

Tidak ada skor integritas pribadi atau nilai kelulusan. Status “Kuat” muncul jika semua kriteria dalam lensa terpenuhi, “Sebagian” jika minimal satu tetapi belum semua, dan “Perlu diperluas” jika belum ada. Setiap kriteria ditampilkan kepada pemain melalui “Bukti dari pilihan Anda”.

| Lensa | Kriteria yang harus seluruhnya terlihat untuk status Kuat |
| --- | --- |
| Nilai & Etika | Misi 2=B; Misi 3=A; intervensi A dan C dipilih. |
| Risiko & Konsekuensi | Misi 1=C; Misi 2=B; Misi 3=A; intervensi B dipilih dan indikator Canvas sesuai dengan intervensi fokus. |
| Kewenangan | Misi 2=B; Misi 3=A; intervensi B dan C dipilih. |
| Dampak Sistemik | Misi 1=C; Misi 3=A; intervensi A, C, dan E dipilih; ketiga hubungan Canvas terhubung. |

Hipotesis awal menentukan teks perkembangan analisis dan tidak menambah/mengurangi status. Menebak persoalan proses sebelum membaca bukti tidak otomatis dianggap lebih baik. Jejak revisi dicatat untuk refleksi tanpa penalti.

## Runtime, penyimpanan, dan SCORM

- Game buildless HTML/CSS/JavaScript, tanpa layanan eksternal atau panggilan AI saat dimainkan.
- HTML tunggal memuat semua gambar/font. ZIP offline memuat sumber dan aset. Tekstur animasi di-inline agar dapat diakses melalui file://.
- Format progres 4, dengan migrasi dari format 3. Pilihan, dependensi antarmisi, scene, batas intervensi, Canvas, dan refleksi diperiksa saat impor.
- Riwayat narasi lokal dibatasi 100 entri. Jejak revisi dibatasi 24 entri terakhir per misi; pilihan pertama tetap disimpan secara terpisah.
- Refleksi Misi 3 dan akhir masing-masing maksimum 300 unit karakter JavaScript. UI menampilkan penghitung.
- Dalam LMS, state ringkas tidak menyimpan seluruh riwayat dialog agar muat pada cmi.suspend_data SCORM 1.2. Hasil dan refleksi tetap tersimpan. Uji payload panjang menghasilkan 2.307 byte dari batas 4.096 byte.
- API: LMSInitialize, LMSGetValue, LMSSetValue, LMSCommit, LMSFinish. API dicari pada window/parent/opener dengan penjagaan akses lintas origin.
- Field: cmi.suspend_data, cmi.core.lesson_location, cmi.core.lesson_status, cmi.core.session_time, cmi.core.exit.
- Status completed ditetapkan setelah tombol penyelesaian pada dialog penutup. Tidak mengirim cmi.core.score atau passed/failed. Status completed sebelumnya tidak diturunkan ketika pemain mengulang untuk latihan.
- Commit dilakukan setelah perubahan state dengan penundaan singkat, saat halaman tersembunyi, dan sebelum keluar. Kegagalan memberi pesan penyimpanan belum dikonfirmasi. Progres LMS didahulukan tanpa mencampurkan progres browser pengguna lain.
- Sesi offline dapat mengekspor JSON dan hasil HTML/TXT. Isi refleksi di-escape sebelum dimasukkan ke HTML hasil unduhan.

Rujukan implementasi SCORM: ADL SCORM 1.2 Conformance Requirements; ADL Cross-Domain Scripting (bagian API); Rustici Software, “A technical guide to SCORM 1.2”, https://scorm.com/scorm-explained/technical-scorm/scorm-12-overview-for-developers/ dan run-time reference chart. Paket ini belum mendapat sertifikasi conformance atau uji pada LMS tujuan.
